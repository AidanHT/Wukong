# mercury_mir_build

Lowers the type-checked Mercury AST into MIR. Sits between `mercury_sema` and the optimizer/backend.

## Layout
- `src/lib.rs` — the entire crate: `lower_program` entry, the `FnLowerer` walker, the free type/op-mapping helpers, and inline `#[cfg(test)]` tests (no `tests/` dir).

## Key types & entry points
- `lower_program(module, sema, interner) -> (Program, Vec<Diagnostic>)` — top-level entry; lowers only `Fn` items that have a body, returns a `mercury_mir::Program` plus diagnostics.
- `lower_fn` — per-function setup: recovers the resolved signature from `sema.defs` (`DefKind::Fn`; falls back to `Ty::Unknown` params / `Ty::Unit` ret if absent), declares all params via `Builder::add_param` first, materializes each, lowers the body, and emits a fallback terminator if it fell through (`ret(None)` for Void, `ret(Some(tail))` if there is a tail value, else `Terminator::Unreachable`).
- `FnLowerer` — the stateful lowerer. Holds the `mercury_mir::Builder`, `sema`/`interner` refs, `diags`, a scope stack (`Vec<HashMap<Symbol, (ValueId, MirType)>>`), a `terminated` flag, and a `loops` stack of `(continue_target, break_target)` `BlockId`s.
- Strategy is **alloca-per-local** (clang-style): every `let`/param gets a stack slot; reads `Load`, writes `Store`. SSA is recovered later by the `mem2reg` opt pass — this crate never reasons about SSA/phi.
- **Matmul → GEMM dispatch** (runs before generic lowering): `recognize_matmul` matches a matmul loop nest — the `ikj` accumulate form (`match_matmul`) and the textbook `ijk` dot-product form (`match_matmul_ijk`), incl. the `C = A·Bᵀ` (`nn.Linear`) spelling. `match_product_ab` classifies the `A*B` factors (normal `B[k*N+j]` vs transposed `B[j*K+k]`); `MatmulNest<'a>` carries `{a,b,c,m,k,n,beta,transposed}` plus per-operand base offsets `{a_off,b_off,c_off}`. `matmul_fn` + `lower_matmul_fn` handle a whole-function matmul (incl. `@parallel`); the `lower_for` hook handles an embedded one. `emit_sgemm` emits an `Op::Call` to one of the four `mercury_sgemm*` symbols (bundled in `GemmSyms`, interned in `lower_program`). Dims may be literals or runtime values. **Batched matmul** (the `ijk` form only): each flattened index may carry a base offset beyond `row*stride+col` (`x[h*S*D + i*K + k]`, the multi-head-attention shape). `match_row_col_off`/`match_product_ab_off` peel the offset off the additive terms (`flatten_add_terms`); `offset_invariant` requires it to be free of the matmul's own `i,j,k`; `emit_sgemm`'s `offset_base` GEPs each base pointer by the offset sum before the kernel call — so each head dispatches. Both backends just execute the resulting `Gep`+`Call`, so no interp/codegen change is needed.
- **Epilogue fusion** (`lower_block` look-ahead, before the elementwise-fusion run): a recognized `nn.Linear` matmul (`transposed`, no offsets) immediately followed by `for i { for j { C[i*N+j] = C[i*N+j] + bias[j] } }` — optionally `fmax(_, 0)` for ReLU — fuses to one `mercury_sgemm_nt_epi` call (`emit_sgemm_epi`, the `nt_epi` symbol in `GemmSyms`). `match_bias_act_epilogue`/`match_epi_value`/`match_c_plus_bias`/`is_c_elem`/`index_of` match the loop strictly (dims/strides/output array/column all verified vs the `MatmulNest`, bias required), so it never misfires; the runtime kernel folds bias+activation into the C writeback. Codes `EPI_ACT_IDENTITY`/`EPI_ACT_RELU` mirror the runtime's.
- **Transcendental → 256-bit AVX2 dispatch**: `try_vmath_for` (sequential) and the head of `try_vectorize_ranged` (`@parallel` per-thread) recognize a loop whose body is one or more independent `out[j] = f(x[j])` activations (`exp`/`log`/`tanh`/`sigmoid`/`silu`/`gelu` over f32) and emit one `mercury_vmath_f32(x+lo, out+lo, hi-lo, op)` call per statement — true 256-bit, the width the generic vectorizer can't reach. `match_vmath_stmt`/`match_vmath_body` are the pure matchers; `emit_vmath_calls` the emitter; `VMATH_*` op codes mirror the runtime's `VM_*`. Tried before the generic vectorizer. `silu`/`gelu` are intrinsics (`math_intrinsic`); their scalar/composed form lowers via `emit_silu`/`emit_gelu`. A multi-statement body (fusion-merged activations) dispatches one call each, in source order.
- **SIMD auto-vectorizer** (in this crate, *not* an opt pass — runs unconditionally so all `-O` levels see the same MIR): `try_vectorize_for` lowers a `for` loop to SIMD. `vectorizable`/`vec_check_value` validate an elementwise body (unit-stride reads/writes, invariant splats, `if`/`else` via if-conversion); `emit_vectorized_for`/`emit_vector_strip`/`emit_scalar_tail` emit an unrolled (`VEC_UNROLL`) main loop + single-vector loop + scalar remainder. `reduction_of`/`emit_reduction` handle the disjoint `s = s + expr(j)` / `s += ..` float-reduction shape with lane accumulators + a horizontal reduce. `vec_lower_value`/`vec_accumulate`/`scalar_accumulate` contract `x + y*z` to `Op::Fma`. `try_contract_fma`/`lower_fma_operand` do the same on the scalar path.
- Free helpers: `mir_ty` (`Ty` -> `MirType`), `mir_ty_of_ast` (used when a `let` has an explicit type annotation), `const_usize_expr` (literal array length), `param_abi_ty`, `arith_binop`/`compound_binop`/`cmp_pred`/`cast_kind` (AST op -> MIR op, float/signed-aware), `is_intrinsic` (`pub`), `parse_int`/`parse_float`. Vectorizer-only: `single_path`, `affine_stride`, `expr_uses_sym`, `vector_width`, `lane_signed`, `set_or_check`, `exprs_struct_eq`.

## Connects to
Upstream: `mercury_ast` (input), `mercury_sema` (`SemaResult`: `sema.types` by `Expr.id`, `sema.defs`), `mercury_types` (`Ty`), `mercury_span` (`Interner`, `Symbol`, `Span`), `mercury_diag`. Builds on `mercury_mir` (`Builder`, `Op`, `MirType`, `BinOp`/`CmpOp`/`CastKind`, `Program`). Downstream: the optimizer (esp. `mem2reg`) and backends consume the `Program`. Tests use `mercury_parser` (dev-dep).

## Gotchas
- **Arrays are not alloca'd as values.** An array local's bound `ValueId` *is* its base pointer: a `Path` read of an array returns the slot directly (no `Load`); indexing `Gep`s off it. Array params get ABI type `Ptr` (`param_abi_ty`) and are bound directly with no slot copy. See `array_parameter_passes_by_pointer` test.
- Unsupported constructs (tensor ops, SIMD/method calls, `for` over non-range, `defer`, unknown calls/places) are a **hard error** via `unsupported` (code `C0001`, message "... not yet supported by codegen") but lowering continues with a placeholder (`const_zero` / fresh alloca) so the rest of the function still lowers. The front end accepts these; only codegen rejects them.
- `terminated` must be reset to `false` after every `switch_to` to a fresh block, or subsequent statements get skipped. Every CFG helper (`lower_while`/`lower_loop`/`lower_for`/`lower_if`/`lower_fill_loop`) does this manually — preserve the pattern when adding new CFG lowering.
- `break`/`continue` read `self.loops.last()` and set `terminated = true`; they only branch when inside a loop (silently no-op otherwise).
- **Vectorizer soundness rests on running pre-opt and identically for both backends.** Elementwise vectorization is bit-identical to scalar (lane `k` == iteration `base+k`). Reduction vectorization *reassociates* the float sum — only sound because the interpreter and native backend execute the *same* vectorized MIR (the differential oracle compares them, not against a strict-scalar reference). Reductions therefore vectorize only via `try_vectorize_for` (sequential), never `try_vectorize_ranged` (the `@parallel` per-thread path — a shared accumulator across threads would race). `Op::Fma` likewise stays exact because the interpreter uses `mul_add`. Don't move vectorization into an opt pass or make it `-O`-conditional, or `-O0` vs `-O2` would diverge.
- **Matmul recognition reassociates** (the GEMM kernel sums in blocked/lane order, not strict
  `ikj`). Sound for the same reason reductions are: native and interpreter call the *identical*
  `mercury_sgemm*` kernel, so the differential oracle still holds. The recognizer is strict (verifies
  every stride) so it never misfires on a non-matmul nest — see the `transposed-B is not row-major`
  negative test. It runs in `lower_for`/`lower_program` *before* generic vectorization.
- The vectorizer caches repeated index loads within a body copy (`vec_loads`, keyed by the index's
  canonical text via `load_key`/`index_canon`), cleared between unroll copies and after any store, so
  `relu`'s `if x[i]>0 {x[i]}` loads `x[i]` once. Don't let it persist across copies (addresses differ).
- Only single-segment paths (`Path::is_single`) and single-index `Index` (`indices.len() == 1`) are handled in `lower_place`/`lower_expr`; multi-index indexing falls through to `unsupported`.
- Op selection is type-driven from sema: float vs int and signedness come from `expr_ty`/`signed` (looked up in `sema.types` by `Expr.id`); a missing type defaults to `Ty::Unknown` / `MirType::I32`.
- `let` element type for arrays prefers the annotation (`mir_ty_of_ast`) over the init expr; `mir_ty_of_ast` falls back to `Ptr` for non-literal array lengths and `I32` for unrecognized scalar names.
- Array-repeat `[v; n]` evaluates `v` once; unrolls to straight-line stores when `n <= REPEAT_UNROLL_LIMIT` (8), else emits a `lower_fill_loop` CFG loop (counter typed `I64`).
- Bool literals lower to `I1` `ConstInt`. Void/unit calls (user fns and intrinsics) emit a void `Call` then return a dummy `const_zero(I32)` so the expression still yields a `ValueId`.
- Int/float literals coerce their MIR type to `I32`/`F32` if the sema type is not int/float.
