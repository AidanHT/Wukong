# mercury_mir_build

Lowers the type-checked Mercury AST into MIR. Sits between `mercury_sema` and the optimizer/backend.

## Layout
- `src/lib.rs` — the entire crate: `lower_program` entry, the `FnLowerer` walker, the free type/op-mapping helpers, and inline `#[cfg(test)]` tests (no `tests/` dir).

## Key types & entry points
- `lower_program(module, sema, interner) -> (Program, Vec<Diagnostic>)` — top-level entry; lowers only `Fn` items that have a body, returns a `mercury_mir::Program` plus diagnostics.
- `lower_fn` — per-function setup: recovers the resolved signature from `sema.defs` (`DefKind::Fn`; falls back to `Ty::Unknown` params / `Ty::Unit` ret if absent), declares all params via `Builder::add_param` first, materializes each, lowers the body, and emits a fallback terminator if it fell through (`ret(None)` for Void, `ret(Some(tail))` if there is a tail value, else `Terminator::Unreachable`).
- `FnLowerer` — the stateful lowerer. Holds the `mercury_mir::Builder`, `sema`/`interner` refs, `diags`, a scope stack (`Vec<HashMap<Symbol, (ValueId, MirType)>>`), a `terminated` flag, and a `loops` stack of `(continue_target, break_target)` `BlockId`s.
- Strategy is **alloca-per-local** (clang-style): every `let`/param gets a stack slot; reads `Load`, writes `Store`. SSA is recovered later by the `mem2reg` opt pass — this crate never reasons about SSA/phi.
- **Matmul → GEMM dispatch** (runs before generic lowering): `recognize_matmul` matches a matmul loop nest — the `ikj` accumulate form (`match_matmul`) and the textbook `ijk` dot-product form (`match_matmul_ijk`), incl. the `C = A·Bᵀ` (`nn.Linear`) spelling. `match_product_ab` classifies the `A*B` factors (normal `B[k*N+j]` vs transposed `B[j*K+k]`); `MatmulNest<'a>` carries `{a,b,c,m,k,n,beta,transposed}` plus per-operand base offsets `{a_off,b_off,c_off}`. `matmul_fn` + `lower_matmul_fn` handle a whole-function matmul (incl. `@parallel`); the `lower_for` hook handles an embedded one. `emit_sgemm` emits an `Op::Call` to one of the four `mercury_sgemm*` symbols (bundled in `GemmSyms`, interned in `lower_program`). Dims may be literals or runtime values. **int8 quantized matmul**: the `u8×i8→i32` `C=A·Bᵀ` `nn.Linear` nest (`s = s + (a[..] as i32)*(b[..] as i32)`, the QNNPACK/oneDNN layout) is recognized by `match_matmul_i8_nt` (the int8 twin of `match_matmul_ijk`: peels the `as i32` casts, enforces A:`u8` × B:`i8` via `scalar_of`, transposed B, no offsets, i32 product/accumulator) and emitted by `emit_i8gemm` as an `Op::Call` to `mercury_i8gemm_nt`/`_parallel` (the `i8nt`/`i8nt_par` `GemmSyms`). `i8matmul_fn` + `lower_i8matmul_fn` handle the whole-function form (checked in `lower_program` *before* the `@parallel` outliner so a parallel int8 kernel reaches the multicore kernel, not a scalar loop); the `lower_for` hook handles the embedded form (passing `self.parallel_fn`). Integer arithmetic, so the kernel equals the scalar nest bit-for-bit in any order (i32 add is associative mod 2³²) — no reassociation exception, unlike the float kernels. **Batched matmul** (the `ijk` form only): each flattened index may carry a base offset beyond `row*stride+col` (`x[h*S*D + i*K + k]`, the multi-head-attention shape). `match_row_col_off`/`match_product_ab_off` peel the offset off the additive terms (`flatten_add_terms`); `offset_invariant` requires it to be free of the matmul's own `i,j,k`; `emit_sgemm`'s `offset_base` GEPs each base pointer by the offset sum before the kernel call — so each head dispatches. Both backends just execute the resulting `Gep`+`Call`, so no interp/codegen change is needed. **bf16/f16 mixed-precision matmul**: `match_matmul_lowp` (the float-accumulator twin of `match_matmul_i8_nt`) recognizes the half nest `s += (a[..] as f32)*(b[..] as f32)` over same-precision `[bf16]`/`[f16]` operands with an f32 accumulator/C, in **two shapes** — NT `C = A·Bᵀ` (nn.Linear forward) and TN `C = Aᵀ·B` (the `dW = dYᵀ·X` weight gradient) — selected by which operand is transposed (**exactly one**, via `match_a_factor`/`match_b_factor`; plain `A·B` and `Aᵀ·Bᵀ` decline). `LowpMatmulNest` carries `{a,b,c,m,k,n,f16,transposed_a}`; `emit_lowp_gemm` routes the 8-way `(parallel, f16, transposed_a)` to `mercury_sgemm_{bf16,f16}_{nt,tn}[_parallel]` (NT feeds the f32 `gemm_dispatch`, TN the f32 `mercury_sgemm_tn` — both on losslessly-widened operands, so bit-exact). Same hooks as the f32/int8 paths: the `lower_for` embedded recognizer + the `lowp_matmul_fn` whole-function `@parallel` interceptor (before the outliner). Wiring is the usual Cranelift sites (the `tn` symbols join the `nt` 7-arg `matches!` membership; the `nt_epi` ones join the 9-arg one) + the interp arm reading bf16/f16 as `u16` bits (NT and TN share the arm — identical flat marshalling, only the runtime fn differs). The fused FFN epilogue (above) is **NT-only** (`try_fuse_lowp_matmul_epilogue` declines `transposed_a`).
- **Epilogue fusion** (`lower_block` look-ahead, before the elementwise-fusion run): a recognized `nn.Linear` matmul (`transposed`, no offsets) immediately followed by `for i { for j { C[i*N+j] = act(C[i*N+j] [+ bias[j]]) } }` fuses to one `mercury_sgemm_nt_epi` call (`emit_sgemm_epi`, the `nt_epi` symbol in `GemmSyms`). The activation `act` is identity (bias-add only), `fmax(_,0)` (ReLU), or a `gelu(…)`/`silu(…)` call — the transformer FFNs; codes `EPI_ACT_IDENTITY`/`RELU`/`GELU`/`SILU` mirror the runtime's. **Bias is optional for the activation forms** (`match_epi_value` returns `Option<bias>`): the bias-free `silu(x·Wᵀ)` **SwiGLU** projection fuses too, emitting a null bias (integer `0`, like the affine-norm null params); identity still requires bias (a bare `C = C` copy is a no-op). `match_bias_act_epilogue`/`match_epi_value`/`match_c_plus_bias`/`is_c_elem`/`index_of` match the loop strictly (dims/strides/output array/column all verified vs the matmul's `(m, n, c)`), so it never misfires; the runtime kernel folds bias+activation into the C writeback (GELU/SiLU reuse `vmath::{gelu1,silu1}`, so fused == unfused). **No interp/codegen change** — the interp already marshals `nt_epi` and passes `act` through; a null bias is distinguished by `Value` variant. **bf16/f16 twin:** `try_fuse_lowp_matmul_epilogue` does the same for a `match_matmul_lowp_nt` (half-input) matmul → `mercury_sgemm_{bf16,f16}_nt_epi[_parallel]` (`emit_lowp_gemm_epi`, the `{bf16,f16}_nt_epi[_par]` symbols), reusing the *identical* `match_bias_act_epilogue` (refactored to take `(m, n, c)` so both nests share it) and `EPI_ACT_*` codes. The widen prepass feeds the same f32 `nt_epi` epilogue, so fused == the f32 fused FFN on the losslessly-widened operands. This twin **does** need new wiring (a/b are u16 pointers): the 4 symbols join the `nt_epi` 9-arg signature in Cranelift's `lower_call` and get a dedicated interp arm (u16-input marshalling like the bf16/f16 GEMM + the `nt_epi` bias/act handling). `@parallel` reaches the multicore kernel through the ordinary `lower_fn(parallel=true)` path (a 2-stmt matmul+epilogue body declines both `lowp_matmul_fn` and `parallel_spec`, which want 1 stmt).
- **Transcendental → 256-bit AVX2 dispatch**: `try_vmath_for` (sequential) and the head of `try_vectorize_ranged` (`@parallel` per-thread) recognize a loop whose body is one or more independent `out[j] = f(x[j])` activations (`exp`/`log`/`tanh`/`sigmoid`/`silu`/`gelu`/`elu`/`leaky_relu`/`softplus`/`mish`/`selu`/`tanhshrink`/`hardsigmoid`/`hardswish` over f32) and emit one `mercury_vmath_f32(x+lo, out+lo, hi-lo, op)` call per statement — true 256-bit, the width the generic vectorizer can't reach. `match_vmath_stmt`/`match_vmath_body` are the pure matchers; `emit_vmath_calls` the emitter; `VMATH_*` op codes mirror the runtime's `VM_*`. Tried before the generic vectorizer. The activations are intrinsics (`math_intrinsic`); each scalar/composed form lowers via its `emit_*` (`emit_silu`/`emit_gelu`/`emit_elu`/`emit_leaky_relu`/`emit_softplus`/`emit_mish`/`emit_selu`/`emit_tanhshrink`/`emit_hardsigmoid`/`emit_hardswish`), which the generic-vectorizer fallback (`vec_lower_value`) also uses per-lane, so a non-dispatched activation still matches. A multi-statement body (fusion-merged activations) dispatches one call each, in source order.
- **`@parallel` reduction → multicore kernel dispatch**: inside a `@parallel` function (lowered via `lower_fn` with `parallel_fn = true`, since `parallel_spec` only matches a single elementwise loop), a recognized reduction loop `for k in 0..n { s += f(x[k], y[k]) }` (or `m = fmax(m, x[k])` / `fmin`) lowers to one `s = s ⊕ mercury_sreduce_f32_parallel(x, y, n, op)` call instead of the sequential vectorizer. `match_reduction_kernel` (pure, strict: single statement, index exactly `k`) classifies dot `x[k]*y[k]`, ssd `(x[k]-y[k])²`, the unary sum `x[k]` (passed `y == x`), and the running **max/min** `fmax(m, x[k])` / `fmin(m, x[k])` (either operand order, `y == x`), and **absmax** `fmax(m, abs(x[k]))` (→ `RED_MAXABS`, the kernel abs's each element — the symmetric int8-quant scale); `try_emit_parallel_reduction` requires `0..n`, an in-scope f32 accumulator, and in-scope arrays, else falls back. `RED_*` codes mirror the runtime's. The outer combine `⊕` is op-aware: an exact f32 `FAdd` for the additive ops (interp rounds f32 in f32, bit-equal to native), or `Cmp(Fogt/Folt)+Select` for max/min — the identical fold the kernel and the sequential `fmax` vectorizer use, so it stays bit-equal. Sequential reductions (incl. fmax/fmin, already handled) keep using `reduction_of`/`emit_reduction` below.
- **Fused normalization → single-pass kernel dispatch** (`lower_block` look-ahead, like the matmul epilogue): an idiomatic in-place flat row normalization folds into one `mercury_norm_f32(x, x, 1, N, eps_bits, NORM_*)` call. Three structurally-disjoint windows are probed (order immaterial): **softmax** (`match_softmax`, 7 stmts: `let m`; `m=fmax(m,x[i])`; `x[i]=exp(x[i]-m)`; `let s=0`; `s+=x[i]`; `let inv=1/s`; `x[i]=x[i]*inv`), **LayerNorm** (`match_layernorm`, 7 stmts: `let s=0`; sum; `let mean=s/N`; `let v=0`; `v+=(x[i]-mean)²`; `let inv=1/sqrt(v/N+eps)`; `x[i]=(x[i]-mean)*inv`), and **RMSNorm** (`match_rmsnorm`, 4 stmts: `let s=0`; `s+=x[i]*x[i]`; `let inv=1/sqrt(s/N+eps)`; `x[i]=x[i]*inv`). All are pure matchers, strict in the same way (every loop ranges `0..N` over the *same* array `x` by its loop var; scalars chain; the internal scalars must not be read after the window — `block_mentions`/`expr_mentions` are the conservative whole-AST use-scan that proves the kernel-hidden scalars don't leak). Helpers: `sum_body_array`/`match_sumsq_body` (sum / sum-of-squares, returning the array), `match_mean`/`match_var_body`/`match_shift_scale_body` (mean, squared-deviation accumulate, center-then-scale), `match_inv_rstd`/`as_rsqrt_arg` (the `1/sqrt(sum/N+eps)` or `rsqrt(...)` reciprocal-std binding, eps as an `f32`-bits literal either side), and `scaled_by_inv_count`/`count_as_f32`/`recip_of_count` (pin the mean/mean-square divisor to the trip count — accepts `/N`, `(N as f32)`, and the kernel-faithful `* (1/N)` literal). The softmax max seed must be `x[0]` or `<= -1e30` so the kernel's true max equals the user's. The LayerNorm/RMSNorm normalize matchers (`match_shift_scale_body`/`match_scale_body`) also peel an optional **affine wrapper** `core * gamma[i] (+ beta[i])` via `peel_affine`/`affine_index` (gamma/beta indexed by the loop var, arrays other than the data), so the *real* transformer norms — a learned per-channel scale γ and shift β — are recognized and `emit_norm` dispatches them to **`mercury_norm_affine_f32(x,x,gamma,beta,1,N,eps,op)`** (an absent param is a null pointer, built as an integer `0` — a `Ptr`-typed const is invalid MIR; the interpreter reads the `Value::Int(0)` as absent by variant). softmax has no affine, so `match_softmax` **rejects** any affine wrapper (declines to the generic vectorizer rather than silently dropping a trailing scale — the differential gate compares interp==native, not against source). `emit_norm` (now taking `rows: Option<&Expr>` — `None`→`rows=1`) is the shared emitter; `NORM_*` mirrors the runtime's. MIR is emitted only on a full match, so a partial match leaves the generic vectorizer + vmath path to lower the loops correctly. Runs pre-opt, so `-O0`==`-O3`; both backends marshal the identical kernel, so the differential gate stays bit-exact. **Batched `[R,C]` norm** (all three: softmax / LayerNorm / RMSNorm — the real `[tokens, hidden]` / attention `[heads*seq, seq]` shape): `for r in 0..R { <norm over x[r*C + i]> }` folds to one `mercury_norm_f32(x, x, R, C, …)`. `index_off`/`is_mul_of` generalize the norm window's data index from `x[i]` to `x[r*C + i]` (the `row*C` base offset, either factor order, `C` matched structurally to the inner bound), threaded through every data-indexing helper (`match_sumsq_body`/`match_scale_body` for RMSNorm; `sum_body_array`/`is_centered`/`match_var_body`/`match_shift_scale_body` for LayerNorm; `match_max_reduce_body`/`match_exp_sub_body`/`match_sum_body` for softmax — whose `x[r*C]` max-seed `is_max_seed` matches via `is_mul_of`); each window matcher takes `batch: Option<Symbol>`. **γ/β stay column-indexed** (per-column, shared across rows). `match_batched_norm` (pure, `&self`) + `try_emit_batched_norm` recognize the outer loop in `lower_for`; the pure matcher also doubles — via the `is_batched_norm_fn` throwaway-`FnLowerer` probe — as a whole-function check run *before* the `@parallel` outliner (mirroring the sgemm/int8 interceptions), so a `@parallel` batched norm dispatches to **`mercury_norm_f32_parallel`** (rows across cores, bit-equal to serial — no cross-row combine) instead of being outlined into per-row vectorized loops. `emit_norm` picks the `_parallel` symbol when `parallel_fn && rows.is_some()` (single-row stays serial). **Note:** RMSNorm is memory-bound, so `@parallel` only wins once the batch spills L3 (see `BENCHMARKS.md`); the serial fused form wins unconditionally.
- **SIMD auto-vectorizer** (in this crate, *not* an opt pass — runs unconditionally so all `-O` levels see the same MIR): `try_vectorize_for` lowers a `for` loop to SIMD. `vectorizable`/`vec_check_value` validate an elementwise body (unit-stride reads/writes, invariant splats, `if`/`else` via if-conversion); `emit_vectorized_for`/`emit_vector_strip`/`emit_scalar_tail` emit an unrolled (`VEC_UNROLL`) main loop + single-vector loop + scalar remainder. `reduction_of`/`emit_reduction` handle the disjoint `s = s + expr(j)` / `s += ..` float-reduction shape with lane accumulators + a horizontal reduce. `vec_lower_value`/`vec_accumulate`/`scalar_accumulate` contract `x + y*z` to `Op::Fma`. `try_contract_fma`/`lower_fma_operand` do the same on the scalar path. **Primitive (non-dispatch) intrinsics** vectorize here too via their lane op: `sqrt`/`rsqrt` (`Op::Sqrt`), `abs` (`emit_abs` = `max(x,-x)` from FSub/Cmp/Select, matching `emit_softplus`'s `|x|`), `fmax`/`fmin` (Cmp+Select), and `round`/`floor`/`ceil`/`trunc` (`Op::Round(RoundMode)`, `round_mode` helper; `round` is ties-to-even). All are bit-identical across backends with no per-backend hand-impl.
- Free helpers: `mir_ty` (`Ty` -> `MirType`), `mir_ty_of_ast` (used when a `let` has an explicit type annotation), `const_usize_expr` (literal array length), `param_abi_ty`, `arith_binop`/`compound_binop`/`cmp_pred`/`cast_kind` (AST op -> MIR op, float/signed-aware), `is_intrinsic` (`pub`), `parse_int`/`parse_float`. Vectorizer-only: `single_path`, `affine_stride`, `expr_uses_sym`, `vector_width`, `lane_signed`, `set_or_check`, `exprs_struct_eq`.

## Connects to
Upstream: `mercury_ast` (input), `mercury_sema` (`SemaResult`: `sema.types` by `Expr.id`, `sema.defs`), `mercury_types` (`Ty`), `mercury_span` (`Interner`, `Symbol`, `Span`), `mercury_diag`. Builds on `mercury_mir` (`Builder`, `Op`, `MirType`, `BinOp`/`CmpOp`/`CastKind`, `Program`). Downstream: the optimizer (esp. `mem2reg`) and backends consume the `Program`. Tests use `mercury_parser` (dev-dep).

## Gotchas
- **Arrays are not alloca'd as values.** An array local's bound `ValueId` *is* its base pointer: a `Path` read of an array returns the slot directly (no `Load`); indexing `Gep`s off it. Array params get ABI type `Ptr` (`param_abi_ty`) and are bound directly with no slot copy. See `array_parameter_passes_by_pointer` test.
- Unsupported constructs (tensor ops, SIMD/method calls, `for` over non-range, `defer`, unknown calls/places) are a **hard error** via `unsupported` (code `C0001`, message "... not yet supported by codegen") but lowering continues with a placeholder (`const_zero` / fresh alloca) so the rest of the function still lowers. The front end accepts these; only codegen rejects them.
- `terminated` must be reset to `false` after every `switch_to` to a fresh block, or subsequent statements get skipped. Every CFG helper (`lower_while`/`lower_loop`/`lower_for`/`lower_if`/`lower_fill_loop`) does this manually — preserve the pattern when adding new CFG lowering.
- `break`/`continue` read `self.loops.last()` and set `terminated = true`; they only branch when inside a loop (silently no-op otherwise).
- **Vectorizer soundness rests on running pre-opt and identically for both backends.** Elementwise vectorization is bit-identical to scalar (lane `k` == iteration `base+k`). Reduction vectorization *reassociates* the float sum — only sound because the interpreter and native backend execute the *same* vectorized MIR (the differential oracle compares them, not against a strict-scalar reference). Reductions therefore vectorize only via `try_vectorize_for` (sequential), never `try_vectorize_ranged` (the `@parallel` per-thread path — a shared accumulator across threads would race). `Op::Fma` likewise stays exact because the interpreter uses `mul_add`. Don't move vectorization into an opt pass or make it `-O`-conditional, or `-O0` vs `-O2` would diverge.
- **Matmul recognition reassociates** (the GEMM kernel sums in blocked/lane order, not strict
  `ikj`). Sound for the same reason reductions are: native and interpreter call the *identical*
  `mercury_sgemm*` kernel, so the differential oracle still holds. The recognizer is strict (verifies
  every stride) so it never misfires on a non-matmul nest — see the `transposed-B is not row-major`
  negative test. It runs in `lower_for`/`lower_program` *before* generic vectorization.
- The vectorizer caches repeated index loads within a body copy (`vec_loads`, keyed by the index's
  canonical text via `load_key`/`index_canon`), cleared between unroll copies and after any store, so
  `relu`'s `if x[i]>0 {x[i]}` loads `x[i]` once. Don't let it persist across copies (addresses differ).
- Only single-segment paths (`Path::is_single`) and single-index `Index` (`indices.len() == 1`) are handled in `lower_place`/`lower_expr`; multi-index indexing falls through to `unsupported`.
- Op selection is type-driven from sema: float vs int and signedness come from `expr_ty`/`signed` (looked up in `sema.types` by `Expr.id`); a missing type defaults to `Ty::Unknown` / `MirType::I32`.
- `let` element type for arrays prefers the annotation (`mir_ty_of_ast`) over the init expr; `mir_ty_of_ast` falls back to `Ptr` for non-literal array lengths and `I32` for unrecognized scalar names.
- Array-repeat `[v; n]` evaluates `v` once; unrolls to straight-line stores when `n <= REPEAT_UNROLL_LIMIT` (8), else emits a `lower_fill_loop` CFG loop (counter typed `I64`).
- Bool literals lower to `I1` `ConstInt`. Void/unit calls (user fns and intrinsics) emit a void `Call` then return a dummy `const_zero(I32)` so the expression still yields a `ValueId`.
- Int/float literals coerce their MIR type to `I32`/`F32` if the sema type is not int/float.
