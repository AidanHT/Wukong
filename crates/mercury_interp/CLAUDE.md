# mercury_interp

Zero-dependency tree-walking MIR interpreter: the always-available backend and the oracle differential tests compare LLVM output against.

## Layout
- `src/lib.rs` — entire crate. `Value`, the `Interpreter` `Backend` impl, the `Interp` evaluator, free helpers (`reg`, `pass_args`, `ptr`, `default_value`, `int_bits`, `mask`, `apply_bin`, `apply_cmp`, `apply_cast`), and the `#[cfg(test)]` module.

## Key types & entry points
- `run` / `run_with_output` (`src/lib.rs`) — public entry points. Take `&Program`, an entry `Symbol`, and `&Interner`. `run` returns the entry's result as an `i64` exit code; `run_with_output` also returns captured stdout bytes.
- `run_kernel_f32` / `run_kernel_i8` — the typed **kernel-entry ABI**: run a kernel function over caller-provided buffers (laid out in flat memory, pointer per array param, copied back on return) instead of via `main`/stdout. The native counterpart is `jit_module().func_ptr()` + a raw call; the full-buffer differential fuzzer runs the same kernel through both and compares the entire output buffer. `run_kernel_i8` is the `u8×i8→i32` int8-GEMM shape (3 params: `a, b, c`).
- `Interpreter` — the `mercury_backend::Backend` impl; `compile` just calls `run_with_output` and wraps it in `Artifact::Executed { exit_code, stdout }`.
- `Accelerator` (`src/lib.rs`) — the **GPU offload seam** (`sgemm_nt`/`vmath`/`norm`/`sreduce`, each `-> Option<Result<…>>`; default impls return `None`). The recognized kernel arms in `intrinsic()` route through `self.accel` when one is installed, else the identical `mercury_runtime` kernel. `run_with_output_accel` / `run_kernel_f32_accel` are the entry points that install one (the driver's `--backend=gpu` path); with no accelerator (every other caller, the differential oracle) the numerics are **byte-for-byte unchanged**. Returning `None` from a method means "fall back to the CPU kernel"; the trait is a plain `dyn` so this crate stays zero-dependency. `Interp` carries a second lifetime `'k` for the `&'k mut dyn Accelerator` (a `&mut` is invariant, so it can't share the covariant program/interner `'a`).
- `Value` — runtime value: `Int(i128)` (width-agnostic, masked per result type), `Float(f64)`, `Ptr(usize)` (index into flat `memory`), `Unit`.
- `Interp<'a>` — per-run state: `program`, `interner`, flat `memory: Vec<Value>`, `stdout`, a `frames` pool of recycled register files, and a `scratch` buffer for block-arg passing.
- `exec` (`src/lib.rs`) — the CFG loop: runs each block's insts, masks int results to their declared width, then dispatches on `Terminator`. `run_function` sets up/recycles a register file; `eval` evaluates one `Op`.

## Connects to
Upstream (runtime deps): `mercury_mir` (`Program`/`Function`/`BasicBlock`/`Op`/`Terminator`/`MirType`/enums), `mercury_span` (`Symbol`/`Interner`), `mercury_backend` (`Backend`/`Artifact`), and `mercury_runtime` (calls its `mercury_sgemm*` kernels so it runs the *identical* GEMM the native backend does). This crate executes MIR; lowering lives in `mercury_mir_build` (a dev-dependency, used only by the test module). Downstream: the `mercuryc` driver (default backend) and `mercury_bench`; the differential oracle for the native/LLVM backends.

## Gotchas
- Memory is a flat `Vec<Value>` with no free/reuse: `Alloca` only ever grows it (an `Array(elem, count)` reserves `count` contiguous slots). Pointers are raw indices; `Gep` is `base + index`. No teardown between calls — fine for short test/bench runs, not a real allocator.
- Two distinct "zero" defaults: register files are sized to `func.value_types.len()` and init to `Value::Unit` (the "undefined"); fresh `memory` slots use typed zeros via `default_value` (`Int(0)`/`Float(0.0)`/`Ptr(0)`). No def-before-use checking; correctness relies on well-formed SSA.
- Int results are normalized via `mask` in `exec` after each inst (`i1` forced to low bit, so `!true == 0`; wider widths sign-extend). `eval` itself only masks `ConstInt`/`Cast` — `Bin`/`Cmp` results are masked by `exec`, not `eval`.
- Div/rem by zero returns `0` (no trap) for SDiv/UDiv/SRem/URem; keep in sync with the LLVM backend or differential tests diverge.
- Intrinsics are dispatched by resolved name when `program.function(func)` is `None`: `print`/`println` (append `"{value}\n"` to stdout), `assert` (returns `Err` on falsy), `mercury_parallel_for` (runs the body over the whole range sequentially), and the GEMM kernels `mercury_sgemm`/`_parallel`/`_nt`/`_nt_parallel` and the int8 `mercury_i8gemm_nt`/`_parallel`. Any other unknown callee errors.
- **GEMM / vmath marshalling.** On a `mercury_sgemm*` call the interpreter reads the `m*k`/`k*n`/`m*n` f32 operands out of its `Value` memory into real `Vec<f32>` buffers, calls the **identical** `mercury_runtime` kernel the native backend calls (the serial one for both serial/parallel names — numerically identical), then writes the result back. The same pattern handles `mercury_vmath_f32(x, out, n, op)` (the 256-bit elementwise transcendental kernel an `out[i]=f(x[i])` loop lowers to): read `n` f32 from x, call the identical kernel, write out (reading all of x first, so in-place `x==out` is correct). And `mercury_sreduce_f32[_parallel](x, y, n, op) -> f32` (the deterministic reduction a `@parallel` dot/ssd/sum, running max/min, or absmax lowers to): read `n` f32 from x and y, call the **serial** `mercury_sreduce_f32` (bit-identical to the parallel one the native backend runs — for the additive *and* the fmax/fmin/maxabs ops, since both forms evaluate the identical fixed-chunk expression tree), return the scalar as a `Value::Float`. And `mercury_norm_f32[_parallel](x, out, rows, cols, eps_bits, op)` (the fused softmax/LayerNorm/RMSNorm a recognized multi-pass norm lowers to): read `rows*cols` f32 from x, call the **serial** kernel (bit-identical to the parallel one — rows are independent), write `out` (reading all of x first, so in-place `x==out` is correct). Its affine sibling `mercury_norm_affine_f32(x, out, gamma, beta, rows, cols, eps_bits, op)` (real LayerNorm/RMSNorm) additionally marshals the `cols`-long gamma/beta arrays; an absent param arrives as a `Value::Int(0)` (the null built as an integer `0`) vs a real array's `Value::Ptr`, so it's distinguished **by variant** and passed as a null pointer. And `mercury_i8gemm_nt[_parallel](a, b, c, m, k, n)` (the int8 quantized `nn.Linear` `C=A·Bᵀ` a `u8×i8→i32` nest lowers to): read `m*k` u8 from a and `n*k` i8 from b (each `Value::Int`'s low byte), call the **serial** `mercury_i8gemm_nt` (bit-identical to the parallel one — rows independent, and i32 add is associative mod 2³², so no reassociation exception even under overflow), write the `m*n` i32 back as `Value::Int`. The same pattern handles the streaming elementwise kernels `mercury_velem_f32(x, y, out, n, a, b, c, op)` (affine + ReLU/ReLU6 map) and `mercury_vhorner_f32(x, out, n, coeffs, ncoeff)` (Horner poly), and the fused-epilogue `mercury_sgemm_nt_epi(a, b, c, m, k, n, beta, bias, act)` — read the operands, call the identical kernel, write back. The epilogue's `bias` may be **null**: a `Value::Int(0)` (the bias-free SwiGLU case) is distinguished from a real array's `Value::Ptr` by variant and passed as `std::ptr::null()`, same convention as the affine-norm gamma/beta. This keeps the differential oracle bit-for-bit exact despite the kernels' wider lanes / reassociated accumulation. (Hence `mercury_runtime` is a runtime dependency now, not just dev.)
- `Terminator::Unreachable` returns an error rather than UB. Infinite-loop guard: a hard step limit of `100_000_000` in `exec` errors instead of hanging.
- `Value::as_int`/`as_float` coerce loosely (`Ptr` -> int, `Unit` -> 0, int <-> float); relies on MIR being type-correct rather than enforcing it.
