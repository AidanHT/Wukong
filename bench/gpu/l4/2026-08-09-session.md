## Findings

**1 — The corpus coverage floors are Windows numbers, and L4 reads HIGHER.**
`gpu-native 235/357` vs `RUN_CORPUS_COVERAGE_FLOOR = 217`; `megakernel 90/103` vs
`MEGA_CORPUS_COVERAGE_FLOOR = 87`. **This is an artifact, not an improvement.** The 256-bit raw-AVX2
vectorizer is Win64-ABI-only, so on Linux `host_supports_vec_kernels()` is false, `wukong_mir_build`
emits no 256-bit recipes, and `lower.rs:743` declines exactly that op
(`{UNSUPPORTED} VecKernelCall`). Fewer `VecKernelCall`s ⇒ more programs lower. The +18/+3 measures
the *host CPU vectorizer being absent*, not the GPU backend being better.
**Consequence:** the metric conflates "what gpu-native can lower" with "did the host vectorizer
fire". If these gates ever run on Linux CI they pass trivially (235 > 217) and can never catch a
coverage regression there. The floor should be platform-aware, or the metric should exclude the
vectorizer. **Open.**

**2 — `try_reserve` is not a guard under Linux overcommit.** Fixed at `84a202b`. It guards the
*reserve*; the following `resize` commits the pages. Windows does not overcommit, so a 3.2 TB request
failed there and the diagnostic fired — green forever. On Linux the reservation succeeds and the
resize faults pages in until the OOM killer fires: **exit 137**, and Modal retried it twice, ~2 h and
~$1. The test that killed the container was
`heap_exhaustion_is_a_diagnostic_not_an_allocator_abort` — the one written to prove this cannot
happen. Now capped at 2^31 slots independent of the allocator. **Closed.**

**3 — A release-only bit-exactness break in `wukong_runtime`. Pre-existing; NOT a Linux bug.**
`colreduce::tests::nan_signed_zero_and_ties_agree_between_paths` FAILS on `ColKind::Sum`
(scalar `0x7FC00000` vs avx2 `0x7FC01234`) and **reproduces byte-identically on Windows in release**,
while passing in debug. `colreduce_scalar` folds `acc + x`; x86 `addps` with two NaN operands returns
SRC1, so the surviving payload depends on operand order — and LLVM does not guarantee NaN payloads
and commutes `a + b` at `-O3` but not `-O0`, while the AVX2 path's order is fixed by intrinsics.
**Meta-finding, worth more than the bug: no gate anywhere runs `cargo test --release`.** The repo
gate and CI are both debug, so the crate whose first invariant is bit-exactness against a scalar twin
is only ever verified in the profile where LLVM does the least. **Open.**

**4 — The runbook's own logging protocol aborted every run.** Fixed at `4ceda63`. §2.2 says to write
the provenance header into `bench/gpu/<dev>/…log` and tee into it, but that path is inside a
`copy=False` mount and Modal kills any run whose mounted files change mid-build. `bench/gpu/**` is
now in `IGNORE` (structurally, not to save bytes — the comment says so at the site). **Closed.**

**5 — The Linux/Windows CPU test-count delta is fully explained.** 861/14 vs 862/16, confined to
`wukong_runtime`, whose `gemm.rs` and `vmath.rs` carry `#[cfg(windows)]` MKL-comparison tests.
Expected per plan §2.6; **not** silent coverage loss. Confirmed rather than assumed, because "a test
passing vacuously where its subject is impossible" is a defect this repo has already hit.

## What Phase 1 answered

- `sm_89` PTX at the new `.version 7.8`/`.target sm_80` floors **loads and runs on a datacenter Ada
  part**, with the whole device suite green and no skips.

  probed **L2 48 MiB** flows into `f16_regime_thresholds` as designed — (32, 96) MiB here vs
